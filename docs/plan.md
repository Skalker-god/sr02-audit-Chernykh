## Відхилення від черги

R19 (D-02) виконано **першим**, хоча його індекс 2,50, а не найвищий. Причина:
R19 змінює публічну сигнатуру `Handout`, і якщо робити його після інших
рефакторингів, доведеться двічі переписувати виклики в тестах і `Program`.
Це відхилення зафіксовано в `docs/decisions.md` (DR-04).

R06 і R03 виконано одразу після R01 у межах групи D-01, а R02 — одразу після
R13 у межах D-12. Це не змінює порядок груп, лише не розриває пов'язані кроки
(DR-05).

## Сім правил безпеки

1. **Зелена база.** Перед першим рефакторингом — `dotnet build` без попереджень
   і `dotnet test` без падінь. Червону базу не рефакторимо.
2. **Один крок — один коміт.** Один тип рефакторингу на коміт; змішувати
   рефакторинг із новою поведінкою заборонено.
3. **Після кожного кроку — збірка й тести.** `dotnet build` = 0 warnings,
   0 errors; `dotnet test` = Failed 0.
4. **Незмінний вивід.** Після кожного кроку вивід програми порівнюється з
   `docs/out-before.txt`; розбіжність — привід відкотити крок.
5. **Тести змінюються лише в місцях виклику.** Якщо R19 змінив сигнатуру,
   змінюються тільки виклики; очікувані значення не переписуються. Кожна
   зміна — в `docs/decisions.md`.
6. **Відкат замість «полагоджу по дорозі».** Якщо тест почервонів — крок
   відкочується (`git reset --hard HEAD~1`), робиться менший крок. «Тимчасові»
   правки тестів під нову поведінку заборонені.
7. **Непокрите — не чіпаємо.** Код без тестів або спостережуваного ефекту
   спочатку отримує тест, а якщо це дорого — запис у борг. Рефакторинг
   «на око» заборонений.

## Критерії завершення

| Показник | Ціль |
|---|---|
| Максимальна CC | ≤ 8 |
| Середня CC | ≤ 4 |
| Найдовший метод | ≤ 40 логічних рядків |
| Вкладеність | ≤ 3 |
| Клони ≥6 рядків | 0 |
| Тести | ≥ 20, Failed 0 |
| Покриття `PickupDesk` | ≥ 60 % |
| Публічні bool-прапорці | 0 |

Якщо метод не вдалося довести до CC ≤ 8 без зміни поведінки — він
потрапляє в `docs/debt.md` з оцінкою PERT, а не «підганяється» під метрику.
